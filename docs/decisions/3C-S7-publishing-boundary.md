# S7 native publishing boundary — 2026-10-05

Native publishing is implemented behind the existing QA render and operation flags. Production and the production Supabase project remain excluded. Installing the migration does not opt projects in or change the default renderer.

The service-only `kcd_publish_source` RPC reads one consistent source containing the owned project, ordered pages, sections and active catalog. The server converts this source to KCD, merges catalog items with the existing 3B publish semantics, checks structural/type/placement/capability/override/colour/security constraints and creates a detached SHA-256 envelope. Native trees remain native; the legacy render projection supplies existing legacy sections and SEO.

The service-only `publish_kcd_document` RPC locks the project and re-reads the source. A mismatch rejects the publish rather than committing content validated against an earlier draft. Operation and page writers already lock this project; additional section/catalog triggers serialize other relevant writes. Domain ownership is checked under an advisory transaction lock. Supersession, deployment insertion, project publish state and history insertion commit together. Any SQL error rolls everything back. This is staged server validation followed by one atomic commit, not JavaScript validation executed inside PostgreSQL.

The database recomputes the hash from the canonical payload and checks its JSON equivalence to the envelope. Browser roles cannot call either publishing RPC or insert forged native deployments. An opted-in draft cannot use the legacy publisher. Native deployment updates may change status only; the envelope, hash, identity, domain, path and timestamps are immutable. Service credentials remain server-side.

The public loader decodes by schema version, checks the stored hash and project identity, and uses the shared SiteRenderer for native trees. Missing schema columns remain compatible with old website-v1 deployments by selecting the existing row rather than requiring new column names. Invalid/future native snapshots never fall back to legacy rendering. Native links use the published site's base path. Single-DOM media rules hide per-device nodes and their link wrappers before hydration; content and layout props use the existing viewport resolution. Fixed editor previews retain explicit-device behavior. Successful native publishing invalidates the old and new public layout paths.

The S6 iframe delta receiver now validates only changed node payloads plus ancestor structure, checks the full resulting tree, and retains unchanged node and page identities. This avoids rendering every tree after each edit. Showing an element also clears saved hidden-prop/page-composition gates atomically while retaining other-device visibility and undo support.

Commit confirmation must match the expected public path, content hash and deployment identity. A database rejection reports failure; a lost response, connection-class SQL error or malformed acknowledgement reports that publication could not be confirmed. The server never retries the commit automatically or promises rollback after an uncertain outcome.

Verification and remaining release gates are recorded in `evidence/3c/s7/README.md`. Nineteen SQL assertions also passed against the real QA PostgreSQL instance with S5/S7 definitions staged inside a transaction. The transaction was rolled back; an independent query confirmed the original data counts and function definitions. These SQL role checks do not establish Supabase JWT gateway behavior, multi-connection race behavior or authenticated browser QA. No persistent remote migrations, deployment, merge, visual sign-off or default-for-new-projects decision occurred.
